## 三句话结论

1. **形象自定义是最大的空位**：现有产品只能靠改文件、造条目或跑 ffmpeg 换形象，没有面向普通用户的上传/导入器。你的 `petpack + 按需生成` 正好命中。
2. **稳定性是最大的不满**：桌面端“不显示且无报错”、全屏游戏被抢焦点、多屏 DPI 错乱、配置丢失——这些抱怨的面积远大于“功能不够”。
3. **语音/识屏/歌词/小游戏是“看起来香、做起来亏”的功能**：竞品在这些方向投入最多，bug 也最密集。首版不建议跟。

## 方法

- 通过 GitHub REST API 拉取 issue 标题与正文（两个主仓库各约 2 页、合计近百条标题，精读 15 条正文）。
- 竞品功能以 README、仓库描述、issue/PR 内容为依据；未核实的能力标记为 `—`，不代表不支持。
- 工作量按“1 名熟悉 TS/React/Electron 的工程师、含单测不含 UI 设计、6 小时/人日”估算；跨平台项额外 +30%–50%。

## 局限

- issue 只代表愿意提问题的那部分用户，沉默用户的需求可能不同。
- 部分竞品功能只从描述判断，未逐行读源码；矩阵中 `—` 即为此类。
- star 数与 issue 数只作规模参考，不代表质量。
