# 借鉴清单与许可证 · dsh-hex-pet

> 对应工程原则：“不熟悉的功能先检索、再比较、后借鉴；不直接复制不兼容或来源不明的代码。”
> 核查时间：2026-10-26。许可证与活跃度以 GitHub API 为准，集成前需再次确认版本与 LICENSE。

## 1. 借鉴流程（每个新能力都走一遍）

1. **检索**：GitHub 搜索同类实现；优先最近 6 个月有提交、issue 有回应、有测试的项目。
2. **看许可证**：MIT / Apache-2.0 / BSD / ISC 可直接参考或复用；GPL/AGPL 只做设计参考，不链接、不打包。
3. **比较**：实现思路、依赖体积、平台覆盖、已知 issue、维护成本，写进本文件的“决策记录”。
4. **选择**：优先“借鉴设计 + 独立实现”；确需复用代码时，记录仓库、commit、文件、许可证，并保留版权声明。
5. **登记**：所有第三方代码/素材进 `THIRD-PARTY.md`；发布前跑一次许可证审计。

## 7. 合规与署名

- 复制 MIT/Apache-2.0 代码时：保留版权声明与许可证文本，在 `THIRD-PARTY.md` 记录仓库、commit、文件、修改说明。
- Apache-2.0 代码修改需标注；专利条款需保留。
- 不复制无 LICENSE、来源不明、闭源逆向得到的代码。
- 不把 GPL/AGPL 代码链接进插件；需要时通过独立进程/用户自装隔离。
- 素材：每条素材记录来源与授权范围；禁商用素材不得进入发行包。
- 发布前检查：`pnpm licenses list` + 人工复核 + 素材清单。
