## 三、本次已修正

### 1. 任务完成状态不会自动结束

**问题**：`StateController` 对 `task-done` 使用旧的 `durationSec`，而当前配置的 `durationSec` 是 0，导致任务完成动作会一直保持。

**修复**：

```text
task-done       → 默认保持 1200 秒（20 分钟）
task-timeout    → 默认保持 300 秒（5 分钟）
balance-warning → 默认保持 120 秒（2 分钟）
```

自定义事件仍兼容旧的 `durationSec`。

### 2. 事件名称不统一

- `approval-needed` 在动作映射里叫「需要批准请求」；
- 在状态/气泡/配置里叫「等待确认」。

已统一为 **等待确认**。

### 3. 桌面右键动作仍显示「（单次）」

右键菜单现在所有动作都只播一次，标签里的「（单次）」已移除。

### 4. 余额警告没有读取按角色映射

`checkBalanceWarning` 之前只读全局 `stateMapping.entries`，现在优先读当前角色包的 `byCharacter` 映射。

### 5. 桌面右键动作会循环

已改为：

```text
选择动作 → 播放一次 → 自动回空闲
```

### 6. 任务完成 / 余额警告的默认时长

已加回归测试，`task-done` 默认 1200 秒。

## 四、仍未闭环的功能 / 已知问题

### P0 · 已补：动作自动跟随 DSH 任务

参考 早期桌宠项目 的 `session/event` 做法，已新增 `AutoTaskDriver`：

| DSH 事件 | 桌宠状态 |
| --- | --- |
| `turn/start` | 任务进行中 |
| `assistant/chunk` / `tool/call` / `tool/result` | 任务进行中（已有任务时不重复触发） |
| `turn/end` | 任务完成 |
| `approval/request` | 等待确认；审批结束恢复任务进行中 |
| 任务开始 10 分钟 | 耗时过长 |
| 超时动作结束 5 分钟 | 回到任务进行中 |
| `assistant/message` 的 token usage | 累计到本次任务，并触发余额检查 |

`/task/start` 和 `/task/end` 也会同步触发对应状态。

**按 session 区分：**

- 只有当前活跃 session 能驱动桌宠；
- 后台 session 的 chunk / turn-end 不会覆盖前台状态；
- 前台 session 结束后，后台 session 在下一次事件时接管；
- 后台 session 的审批不会抢当前桌宠。

**仍然存在的限制：**

- 余额警告结束后：有任务回到任务动作，没有任务回到空闲；
- 审批和 `turn/end` 极端并发时可能有一次状态先后覆盖；
- 没有真正的优先级队列，仍是单状态覆盖 + 审批保护。

### P0 · 已补：SSE 即时推送

新增：

```text
GET /dsh-xiaofu/state/events
```

- 网页用 `EventSource` 订阅；
- 桌面 helper 用 `EventSource` 订阅；
- 断线时保留 2–3 秒轮询兜底；
- 已实测收到 `state: null` 和 `task-start` 推送帧。

### P1 · 状态没有完整优先级和恢复逻辑

当前任意新状态会直接覆盖旧状态：

- 「等待确认」在审批期间被保护，但手动触发仍可能覆盖；
- 超时结束后会回到「任务进行中」，但不会恢复超时前的具体子状态；
- 任务完成和超时同时发生时，后触发者覆盖前者。

目前是“单状态覆盖 + 审批保护”，不是完整状态机。

### P1 · 桌面「打开对话」只聚焦客户端

`dsh://open` 只能把 DSH 客户端拉到前台，不能定位到具体对话页。  
动作名「打开对话」在桌面端实际效果是「打开/聚焦 DSH」。

### P1 · 单击/双击已支持多选轮播

默认：

```json
"clickAction": "animation",
"clickAnimation": "animations/click.webm",
"clickAnimations": []
```

设置页可以多选：

- 每次点击播放下一个；
- 播放中再次点击立即切下一个；
- 播完回到点击前状态；
- 不选时自动寻找 `click/tap`。

### P2 · 文档与实际菜单不一致

以下文档仍引用已删除的菜单项：

- `docs/FEATURE-TOGGLES.md`：显示位置 / 关于 / 恢复默认
- `docs/SETTINGS-IA-REVIEW.md`：旧「点击行为」
- `README.md`：单测数量已同步为 82

### P2 · 部分动作源视频清晰度受源素材限制

- 「打盹」「看沙漏」「真的没了」源视频为 1280×720；
- AI 生成边缘有柔光/半透明过渡；
- 已按「等待确认」的软 alpha 流程处理，但无法超过源视频边缘质量。
