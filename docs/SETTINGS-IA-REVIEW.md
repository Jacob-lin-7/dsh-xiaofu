# 设置导航与新手流程梳理

> 视角：一个刚下载 `dsh-hex-pet` 的新用户，从「装好插件」到「拥有自己的角色、动作、对话」。
>
> 目标：把现在 12 个设置入口，收敛成 6 个用户能一眼看懂的大类；内部工具收进「高级」。

---

## 1. 新用户实际会走的路径

```text
安装插件
  ↓
打开设置，先看到一只默认宠物
  ↓
① 换角色 / 上传角色
  ↓
② 设展示：网页还是桌面、多大、在哪个角
  ↓
③ 配动作：空闲、任务进行中、任务完成、审批、超时、余额警告
  ↓
④ 配对话：气泡样式、字体、每个状态说什么
  ↓
⑤ 配互动：点击做什么、有没有音效
  ↓
⑥ 桌面试跑、调位置、收工
```

真正会反复回来的只有 4 件事：

1. 换角色 / 换动作；
2. 改某句台词或气泡样式；
3. 调大小、位置、显示在哪；
4. 桌面出问题时启动/停止/重载。

「功能开关、编码器、帧序列生成、碎碎念」不是日常路径。

## 2. 当前 12 个入口盘点

| 当前入口 | 实际内容 | 使用频率 | 主要问题 | 建议 |
| --- | --- | --- | --- | --- |
| 宠物 | 多宠物标签、名字、大小、位置、显示方式、启动/停止 | 高 | 和「角色」概念重叠；多数人只有一只 | 合并到「角色」+「展示」；多宠物收进高级 |
| 功能 | 核心/交互/外观/显示/状态/系统功能开关 | 低 | 和具体设置重复；新手看不懂 | 收进「高级 · 功能开关」 |
| 角色 | 上传角色 zip、角色列表、预览、切换、删除 | 高 | 名字清楚，但和「宠物」重复 | 保留为「角色 · 角色库」 |
| 表情 | 上传/管理表情图，气泡可引用 | 低 | 只在对话里用，却单开一栏 | 合并到「对话 · 表情」 |
| 对话 | 气泡样式、自定义气泡、字体、字号、台词、时长/间隔 | 高 | 内容已经很完整，名称可以更聚焦 | 保留为「对话」 |
| 动作 | 动作库上传/改名、6 个事件的动作映射、轮换、维持时间 | 高 | 「动作」和「状态」混用；动作库没有删除 | 保留为「动作」，内部再分「动作库 / 动作映射」 |
| 生成 | 帧序列生成 webm、任务历史、清理 | 低 | 新手会误以为「文生角色」；实验性 | 收进「动作 · 制作动作」或高级 |
| 交互 | 左键点击行为（无/动画/打开 DSH/对话） | 中 | 名字太大，实际只有点击 | 改名「互动」，把音效并进来 |
| 展示 | 桌面模式、启动/停止/重载、逐只显示/大小/位置/托盘 | 高 | 「桌面模式（实验）」太技术 | 改名「展示」，作为一级入口 |
| 声音 | 点击音效上传、音量 | 低 | 和「交互」强相关却分开 | 合并到「互动 · 音效」 |
| 碎碎念 | LLM 定时生成一句闲聊 | 低 | 名字不直观；需要配置 LLM | 改名「AI 闲聊」，收进高级，默认关闭 |
| 编码器 | ffmpeg 检测/下载/状态 | 极低 | 内部依赖，用户不该关心 | 收进「高级 · 视频工具」，只在缺失时提示 |

当前导航：

```text
宠物 / 功能 / 角色 / 表情 / 对话 / 动作 / 生成 / 交互 / 展示 / 声音 / 碎碎念 / 编码器
```

---

## 3. 核心问题

### 3.1 概念重复

- **角色 / 宠物 / 形象**：三个词都在用。用户不知道「角色」是素材包，「宠物」是实例。
- **动作 / 状态**：动作映射其实在配「什么事件播什么动作」，但「状态」又指任务状态。
- **对话 / 气泡 / 表情 / 声音**：本来是一条体验链，被拆成四个入口。

### 3.2 内部工具暴露给用户

- 功能开关：多数是开发/兼容开关；
- 编码器：ffmpeg 依赖；
- 帧序列生成：实验性制作工具；
- 碎碎念：需要 LLM 配置的高级玩法。

### 3.3 新手不知道先做什么

现在打开设置，第一眼是 12 个平级入口，没有「先角色、再动作、再对话」的顺序提示。

## 4. 建议的 6 个一级入口

```text
角色
  我的角色
  角色库
  尺寸与位置

动作
  动作库
  动作映射
  制作动作（高级）

对话
  气泡
  字体
  台词
  表情

互动
  点击行为
  音效
  拖拽 / 漫游

展示
  显示方式
  桌面窗口
  多屏与位置

高级
  功能开关
  多宠物
  AI 闲聊
  视频工具
  诊断
```

一级只留 6 个：

```text
角色 / 动作 / 对话 / 互动 / 展示 / 高级
```

## 6. 名称优化

| 现在 | 建议 | 理由 |
| --- | --- | --- |
| 宠物 | 我的角色 | 用户养的是角色，不是「实例」 |
| 角色 | 角色库 | 和「我的角色」区分：一个是用，一个是库 |
| 动作 | 动作 | 保留；内部用「动作库 / 动作映射」 |
| 生成 | 制作动作 | 说明产出的是动作，不是角色 |
| 交互 | 互动 | 更口语 |
| 展示 | 展示 | 已改，比「桌面模式（实验）」直观 |
| 声音 | 音效 | 实际只有点击音效 |
| 碎碎念 | AI 闲聊 | 不用猜「碎碎念」是什么 |
| 编码器 | 视频工具 | 不暴露 ffmpeg 术语 |
| 功能 | 高级功能 | 明确不是日常设置 |

## 7. 建议隐藏 / 删除

### 直接隐藏（保留代码，收进高级）

- 功能开关；
- 编码器；
- 帧序列生成；
- AI 闲聊；
- 多宠物管理；
- 诊断/重载/仅网页等排障按钮。

### 可以删除的重复项

- 已经 `display:none` 的「外观 / 字体字号」卡片；
- 「声音」独立入口（并入互动后）；
- 「表情」独立入口（并入对话后）；
- 「生成」独立入口（并入动作后）。

### 不建议删的能力

- 角色包上传/切换/删除；
- 动作库上传/改名/多动作轮换；
- 动作映射 6 个固定事件；
- 气泡样式、字体、台词、时长/间隔；
- 展示方式、桌面启停、大小位置；
- 点击行为与音效。

## 8. 新用户首启流程

建议第一次打开时做一个 3 步引导，而不是直接给 12 个入口：

```text
第 1 步：选一个角色
  - 用内置占位
  - 上传角色包
  - 去「制作角色」看 SOP

第 2 步：放在哪里
  - 网页 / 桌面 / 两者
  - 大小、角落

第 3 步：试一下
  - 点它
  - 切「任务进行中」
  - 看气泡和动作是否正常
```

完成后进入「常用设置」：

```text
角色 / 动作 / 对话 / 互动 / 展示
```

「高级」放在右上角齿轮，不参与首启。

---

## 9. 优先级

### P0：不改功能，只改信息架构

1. 把 12 个导航合并成 6 个；
2. 「声音」并入「互动」，「表情」并入「对话」；
3. 「生成」「功能」「编码器」「碎碎念」收进高级；
4. 统一「角色 / 宠物 / 形象」叫法。

### P1：补用户实际会用的缺口

1. 动作库支持删除动作；
2. 动作映射的「角色」下拉和动作库保持同步；
3. 保存后给明确的「已生效 / 需重启」提示；
4. 首次进入给 3 步引导。

### P2：高级能力

1. DSH 自动事件（running / waiting / done / 超时 / 余额）自动触发；
2. 桌面端动作轮换；
3. 导入/导出整套角色配置。

---

## 10. 一句话结论

现在不是功能不够，而是**功能都平铺在导航里**。

保留 6 个一级入口，把「角色 → 动作 → 对话 → 互动 → 展示」做成一条顺手的链路，其余全部收进「高级」，新用户就能一眼知道：

> 这个插件可以换角色、配动作、改台词和气泡、调大小位置、放到桌面上。
